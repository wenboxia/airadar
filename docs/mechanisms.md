# 机制人话讲解（面试脱稿讲这一份）

> 每个机制回答三件事：解决什么问题 / 怎么做的 / 面试被追问时怎么答。
> 技术细节在 `decisions.md`，这里只讲人话。

## 1. 信源分层（Tier 体系）

**问题**：AI 领域每天几百条信息，90% 是噪声。怎么让机器知道谁可信？

**做法**：给每个信源打一个信誉等级，等级决定它的**基础分**，也决定它有没有资格自动发布。目前 19 个信源：

| 等级 | 基础分 | 准入逻辑（为什么是这一级） | 实际有哪些 |
|---|---|---|---|
| **S** 官方一手 | 90 | 信息来自产品/技术的创造者本人，不存在转述失真 | OpenAI News、Anthropic News、Google DeepMind、GitHub Blog、Hugging Face Blog、MCP 官方博客、arXiv |
| **A** 公认专家 | 78 | 作者在该领域有**被验证过的判断力**，其分析独立于官方口径 | Simon Willison、Andrej Karpathy、Lilian Weng、Hacker News 高分帖（社区集体判断） |
| **B** 垂直媒体 / 社区信号 | 62 | 有编辑或社区筛选，但不是一手，也不保证判断力 | GitHub Trending（近 30 天高星 AI 仓库）、量子位 |
| **C** 投资 / 研究 / 跨界视角 | 48 | 不直接生产工程内容，但提供**技术趋势背后的产业逻辑和批判视角** | Dwarkesh Podcast（深度长访谈）、AI Snake Oil（Princeton 研究者的批判声音）、Import AI（Jack Clark，研究+政策+产业） |
| **D** 待观察 | 30 | **在本系统里还没有信誉记录**——强制人工过审，永不自动发布 | Latent Space、Interconnects、Eugene Yan |
| **X** 已屏蔽 | 0 | 验证过存在抄袭/标题党/纯软文 | 目前为空（机制已就位，还没遇到需要屏蔽的） |

**追问怎么答**：

- *"为什么不直接用一个权重数字？"* 因为等级背后是**准入逻辑**，不是拍脑袋的数字。有逻辑才能解释、才能让新信源按规则入库、才能在争议时说清为什么。

- *"D 级里的 Latent Space、Eugene Yan 质量明明很高，为什么放最低级？"* **这正是设计的关键。**它们放 D 级不是因为差，而是因为**在我的系统里还没有信誉记录**。所有新信源一律从 D 级进入、强制人工过审；人工连续通过率高了，系统会给出升级建议。所以 tier 不是我手工贴的静态标签，而是**有升降通道的信誉记录**——信誉是挣来的，不是我赐的。

- *"C 级为什么要收批判性的声音（AI Snake Oil）？"* 刻意的。如果只收官方发布和乐观派分析，知识库会变成信息茧房。C 级引入"反面声音"和产业约束视角（比如 Dwarkesh 的长访谈里讲算力和供应链的现实约束），是为了让判断有对照面。

- *"微信公众号怎么处理？"* **载体无罪，看运营主体**。字节跳动技术团队的公众号和它的官网博客权威性是等价的；我们建的是"运营主体信誉库"，不是"平台黑名单"。

- *"X 级为什么是空的？"* 因为还没遇到需要永久屏蔽的信源。机制已就位（抓取阶段直接跳过 X 级），但我不会为了凑满六级去编几个进去——**空着比编造诚实**。

## 2. 置信度路由（HITL 的核心）

**问题**：全自动会放走坏内容，全人工又回到了人力瓶颈。

**做法**：每条内容算一个综合分 = 信源等级基础分 × 55% + 模型对内容价值的评分 × 45%。然后三分支：高分自动发布、中间区**开 GitHub Issue 给我勾选审批**、低分丢弃但仍然入库留审计记录。

**追问怎么答**：
- *"为什么中间区交给人？"* 因为这是**系统知道自己不确定的区域**。Agent 的成熟度不体现在"什么都敢自己决定"，而体现在"知道什么时候该问人"。
- *"人的决策怎么形成闭环？"* 每次审批都写进 `feedback.jsonl`，汇总成信源的**边缘区处理策略**建议——这就是数据飞轮。

- *"飞轮踩过什么坑？"*（这段最值钱）首次回收 18 条审批后，数据显示 **S 级的 OpenAI News 通过率 0/4，而 B 级的 GitHub Trending 是 3/9**。看起来像"信源分层失效，该给 OpenAI 降级"。**但这是错的**——人工反馈只来自中间区（高分自动发了、低分直接丢了），所以它是**条件概率**：P(认可 | 落在边缘区)。OpenAI 的好内容全在高分区，落到边缘区的恰恰是营销软文；GitHub Trending 没有营销稿，边缘内容依然是具体技术产出。所以飞轮只能用来调**边缘区的处理策略**，绝不能用来改 tier——**用有偏样本推翻无偏结论是统计硬错误**。任何"用线上行为反馈做优化"的系统都要先问：这批数据是怎么采样出来的？

## 3. 兜底降级（三条降级链）

**问题**：外部依赖都会挂——信源会 403，模型会限流，账户会欠费。

**做法**：三条同构的降级链。
- **内容获取链**：直接抓取 → Jina Reader 提取服务 → 保留 RSS 简介。（真实案例：OpenAI 官网用 Cloudflare 挡掉一切非浏览器请求，连浏览器 UA 都是 403，最后靠 Reader 拿到 6000 字正文）
- **模型调用链**：主力 DeepSeek → 备用 GLM → 全挂则标记不可用。
- **业务降级**：模型不可用时，S/A 级放行、其余全部送人工审；摘要做不了就"仅标题+链接"入库并打标。

**追问怎么答**：
- *"降级的方向怎么定？"* **保守降级**——宁可多麻烦人，不可错发内容。降级时收紧自动化权限而不是放宽，因为发布质量是产品信任的底线。
- *"怎么证明兜底真的有效？"* 我在三家账户都欠费的真实环境下做过一次完整的降级演练，pipeline 照常跑完并正常发布了内容。而且写了 12 个回归测试锁住这套逻辑。

## 4. 幻觉治理

**问题**：模型会编。

**做法**：三层。
1. **架构层**：不让模型自己联网，而是我们抓到原文再喂给它——**没有原文就没法查幻觉**。
2. **检测层**：摘要生成后，再让模型对照原文核验一遍，发现无依据的断言就打标记。
3. **根因层**：发现幻觉后**先归因再修**。

**追问怎么答（这是最有价值的一段）**：
真实案例——检测层抓到一条：摘要写"让**全公司员工都能构建软件**"，原文只说"让软件开发在企业内变得**可及**"。归因下来发现**不是模型不老实，是我们的 prompt 逼它编**：只给它 150 字的简介却要求写 300 字摘要，缺的信息只能靠猜。

所以修法不是换个更强的模型，而是改机制：原文太短时进入"简介模式"，只写一句话、明确告诉模型"你拿到的只是简介，绝对不许推测扩写"。

旁证：Kimi 只看标题时曾编造"这是 Anthropic 的愚人节玩笑文章"，喂上原文后判断完全准确——**信息不足是幻觉的第一诱因**。

## 5. 模型适配层

**问题**：三家都号称"OpenAI 兼容"，但接上去两家直接报错。

**做法**：一张 `MODEL_QUIRKS` 表按模型名前缀声明每家的怪癖，调用逻辑不变。

**追问怎么答**：
- *"具体遇到了什么？"* ① Kimi k3 只接受 temperature=1，传别的值直接 400。② **三家旗舰全是推理模型，内部思考的 token 也算进 max_tokens**——实测 GLM 在 max_tokens=300 时思考就用掉 299，返回空内容。这个坑不知道的话，线上会遇到"模型莫名返回空"且极难排查。
- *"为什么做成表而不是 if-else？"* 怪癖是**数据**不是**逻辑**。新增模型只改表，不动调用代码。

## 6. 评测体系

**问题**：怎么证明"效果变好了"不是错觉？

**做法**：
- **黄金测试集**：我人工标注的 30-100 条"标准答案"（该不该收、属于什么分类），算筛选的 precision/recall 和分类准确率。
- **规则校验**：字段完整性、链接合法性、状态合法性——零成本、每次必跑。
- **LLM-as-Judge**：用 **Kimi**（与主力 DeepSeek 不同家）当裁判评摘要忠实度。
- **回归对比**：每次结果存档，跨版本可比。

**追问怎么答**：
- *"为什么裁判要换一家？"* 模型给自己的输出打分会系统性偏高（self-preference bias）。自己人评自己人的结果不可信。
- *"黄金集怎么标？"* 标准是"三个月后你还愿意在库里搜到它吗"。**边界样本比典型样本值钱**——营销软文、重复报道、高质量但领域无关的内容，这些才能测出筛选器的真实水平。

- *"单元测试测什么？"*（23 个回归测试）真实案例：我给"D 级信源永不自动发布"这条规则写测试时，测试失败了——追下去发现 D 级的分数上限只有 61.5 分，够不到 75 的发布线，**所以那条显式的守卫规则从来没执行过**。保护是生效的，但它靠的是算术碰巧，不是规则本身；只要有人调一下参数，保护就静默消失。所以我把测试改成**验证安全网本身**：临时调低发布线模拟未来的配置变更，确认守卫真的会兜住。**测"当前结果对不对"只能防今天的错，测"不变量在参数变化下是否成立"才能防明天的错。**
