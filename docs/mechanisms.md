# 机制人话讲解（面试脱稿讲这一份）

> 每个机制回答三件事：解决什么问题 / 怎么做的 / 面试被追问时怎么答。
> 技术细节在 `decisions.md`，这里只讲人话。

## 1. 信源分层（Tier 体系）

**问题**：AI 领域每天几百条信息，90% 是噪声。怎么让机器知道谁可信？

**做法**：给每个信源打一个信誉等级 S/A/B/C/D/X。S 是官方一手（OpenAI、Anthropic 官方博客、arXiv），A 是公认专家的个人博客（Simon Willison、Karpathy），B 是垂直媒体和社区信号，D 是新发现的待观察信源，X 是已验证的垃圾源直接屏蔽。等级决定这条内容的**基础分**，也决定它有没有资格自动发布——**D 级信源永远不能自动发布，必须人工过一遍**，因为它还没有信誉记录。

**追问怎么答**：
- *"为什么不直接用一个权重数字？"* 因为等级背后是**准入逻辑**，不是拍脑袋的数字。S 级的逻辑是"信息来自创造者本人，不存在转述失真"；A 级的逻辑是"作者在该领域有被验证过的判断力"。有逻辑才能解释、才能让新信源按规则入库。
- *"微信公众号怎么处理？"* **载体无罪，看运营主体**。字节跳动技术团队的公众号和它的官网博客权威性是等价的；我们建的是"运营主体信誉库"，不是"平台黑名单"。

## 2. 置信度路由（HITL 的核心）

**问题**：全自动会放走坏内容，全人工又回到了人力瓶颈。

**做法**：每条内容算一个综合分 = 信源等级基础分 × 55% + 模型对内容价值的评分 × 45%。然后三分支：高分自动发布、中间区**开 GitHub Issue 给我勾选审批**、低分丢弃但仍然入库留审计记录。

**追问怎么答**：
- *"为什么中间区交给人？"* 因为这是**系统知道自己不确定的区域**。Agent 的成熟度不体现在"什么都敢自己决定"，而体现在"知道什么时候该问人"。
- *"人的决策怎么形成闭环？"* 每次审批都写进 `feedback.jsonl`。某个信源如果连续多条被我否掉，系统会给出**降级它的 tier 的建议**——这就是数据飞轮。

## 3. 兜底降级（三条降级链）

**问题**：外部依赖都会挂——信源会 403，模型会限流，账户会欠费。

**做法**：三条同构的降级链。
- **内容获取链**：直接抓取 → Jina Reader 提取服务 → 保留 RSS 简介。（真实案例：OpenAI 官网用 Cloudflare 挡掉一切非浏览器请求，连浏览器 UA 都是 403，最后靠 Reader 拿到 6000 字正文）
- **模型调用链**：主力 DeepSeek → 备用 GLM → 全挂则标记不可用。
- **业务降级**：模型不可用时，S/A 级放行、其余全部送人工审；摘要做不了就"仅标题+链接"入库并打标。

**追问怎么答**：
- *"降级的方向怎么定？"* **保守降级**——宁可多麻烦人，不可错发内容。降级时收紧自动化权限而不是放宽，因为发布质量是产品信任的底线。
- *"怎么证明兜底真的有效？"* 我在三家账户都欠费的真实环境下做过一次完整的降级演练，pipeline 照常跑完并正常发布了内容。而且写了 12 个回归测试锁住这套逻辑。

## 4. 幻觉治理

**问题**：模型会编。

**做法**：三层。
1. **架构层**：不让模型自己联网，而是我们抓到原文再喂给它——**没有原文就没法查幻觉**。
2. **检测层**：摘要生成后，再让模型对照原文核验一遍，发现无依据的断言就打标记。
3. **根因层**：发现幻觉后**先归因再修**。

**追问怎么答（这是最有价值的一段）**：
真实案例——检测层抓到一条：摘要写"让**全公司员工都能构建软件**"，原文只说"让软件开发在企业内变得**可及**"。归因下来发现**不是模型不老实，是我们的 prompt 逼它编**：只给它 150 字的简介却要求写 300 字摘要，缺的信息只能靠猜。

所以修法不是换个更强的模型，而是改机制：原文太短时进入"简介模式"，只写一句话、明确告诉模型"你拿到的只是简介，绝对不许推测扩写"。

旁证：Kimi 只看标题时曾编造"这是 Anthropic 的愚人节玩笑文章"，喂上原文后判断完全准确——**信息不足是幻觉的第一诱因**。

## 5. 模型适配层

**问题**：三家都号称"OpenAI 兼容"，但接上去两家直接报错。

**做法**：一张 `MODEL_QUIRKS` 表按模型名前缀声明每家的怪癖，调用逻辑不变。

**追问怎么答**：
- *"具体遇到了什么？"* ① Kimi k3 只接受 temperature=1，传别的值直接 400。② **三家旗舰全是推理模型，内部思考的 token 也算进 max_tokens**——实测 GLM 在 max_tokens=300 时思考就用掉 299，返回空内容。这个坑不知道的话，线上会遇到"模型莫名返回空"且极难排查。
- *"为什么做成表而不是 if-else？"* 怪癖是**数据**不是**逻辑**。新增模型只改表，不动调用代码。

## 6. 评测体系

**问题**：怎么证明"效果变好了"不是错觉？

**做法**：
- **黄金测试集**：我人工标注的 30-100 条"标准答案"（该不该收、属于什么分类），算筛选的 precision/recall 和分类准确率。
- **规则校验**：字段完整性、链接合法性、状态合法性——零成本、每次必跑。
- **LLM-as-Judge**：用 **Kimi**（与主力 DeepSeek 不同家）当裁判评摘要忠实度。
- **回归对比**：每次结果存档，跨版本可比。

**追问怎么答**：
- *"为什么裁判要换一家？"* 模型给自己的输出打分会系统性偏高（self-preference bias）。自己人评自己人的结果不可信。
- *"黄金集怎么标？"* 标准是"三个月后你还愿意在库里搜到它吗"。**边界样本比典型样本值钱**——营销软文、重复报道、高质量但领域无关的内容，这些才能测出筛选器的真实水平。
