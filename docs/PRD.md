# AIRadar PRD

> 每天扫描 AI 前沿、沉淀为知识库的情报 Agent。
> 本文档记录产品定义；机制的"为什么"见 `decisions.md`，实现见 `pipeline/`。

## 1. 要解决的问题

AI 领域每天产生数百篇论文、数十个开源项目、海量博客与公众号文章。从业者的三个真实痛点：

1. **信息过载**：人工遍历信源每天要 1 小时以上，且 90% 是噪声（重复报道、营销软文、标题党）；
2. **信任缺失**：野鸡来源与权威来源混在同一个 feed 里，判断可信度要额外花精力；
3. **看完即忘**：资讯消费是一次性的，三个月前看过的"Agent 记忆架构"文章想找找不回来，话题的演进脉络没人帮你串。

AIRadar 的回答：**它知道谁可信（信源分层）、知道自己错没错（评测体系）、知道什么时候该问人（置信度路由 HITL）、记得住看过什么（记忆分层）。**

## 2. 目标用户

第一用户是项目主人自己（AI 产品经理求职者，日常需要高频跟进 agent 工程/模型动态/评测方法论）。泛化用户画像：AI 从业者/求职者，有持续跟进需求但没时间遍历信源，需要"已经提炼到可直接消费"的内容+可回溯的知识库。

## 3. 竞品分析（2026-08-27 联网扫描 + 人工调研）

### 3.1 商业 Newsletter 类

| 竞品 | 形态 | 优势 | 没做的事 |
|---|---|---|---|
| TLDR AI | 人工精选日报，125 万订阅 | 覆盖广、人工质检 | 无知识沉淀、无个性化、不可检索 |
| AlphaSignal | 研究向周报（"by researchers, for researchers"） | 技术深度 | 同上，纯 feed 消费 |
| smol.ai AI News | **LLM 全自动**日报（Twitter/Discord 回收，~5 万订阅） | 自动化程度高、时效快 | 无信源信誉体系、无评测、无人工兜底，噪声偏高 |
| aiweekly.co | 人工+算法周报，运营 11 年 | "AI Attention"趋势指数（值得借鉴） | 无知识库、无问答 |
| 技术周刊 AIoT小报（美团内部） | 纯人工编辑周刊 | 双层摘要、[来源] 前缀信任标注（已借鉴） | 人力瓶颈、无 AI 化、无沉淀 |

### 3.3 结论：差异化定位

所有已知竞品都停在"聚合+摘要+推送"。AIRadar 的四个差异化没有任何一家同时具备：
**①可解释的信源信誉分层（不是一个 weight 数字，是有准入逻辑的 Tier 体系+反馈回流）
②全 pipeline 评测（黄金集 precision/recall + LLM-as-Judge 幻觉率，竞品全部为零）
③记忆分层（短期 feed / 中期话题热度与生命周期 / 长期精华时间线）
④置信度路由 HITL（系统知道自己什么时候不确定，主动问人，决策回流成数据飞轮）**

这四件事恰好是 AI 产品岗 JD 里最值钱的四块能力——选题即论证。

## 4. 信源分层设计（核心资产，实现在 pipeline/sources.yaml）

| Tier | 准入逻辑 | 处理策略 | 例子 |
|---|---|---|---|
| S | 官方一手来源（产品/技术的创造者本人发布） | 自动收录，基础分 90 | OpenAI/Anthropic/DeepMind 官方、arXiv、MCP 官方 |
| A | 公认专家个人博客（领域内有验证过的判断力） | 优先收录，基础分 78 | Simon Willison、Karpathy、Lilian Weng |
| B | 大厂子品牌/垂直媒体/社区信号 | 按主题收录，基础分 62 | GitHub Trending、机器之心 |
| C | 投资/研究/跨界视角 | 补充收录，基础分 48 | Dwarkesh Podcast、AI Snake Oil、Import AI |
| D | 待观察新信源 | **强制进人工审核，永不自动发布**，基础分 30 | Latent Space、Interconnects、Eugene Yan |
| X | 已验证低质（抄袭/标题党/软文） | 直接屏蔽，留日志 | 目前为空——机制就位，尚未遇到需屏蔽的源 |

**当前 19 个信源**（S 7 / A 4 / B 2 / C 3 / D 3 / X 0）。完整清单由 pipeline 从 `sources.yaml` 导出到 `stats.json`，前端「机制」页实时渲染——**展示层从唯一事实来源派生，不硬编码**（D21 的教训）。

**信誉是挣来的，不是赐的**：D 级里的 Latent Space、Eugene Yan 质量其实很高，放最低级不是因为它们差，而是**在本系统里还没有信誉记录**。所有新信源一律从 D 级进入、强制人工过审，通过率持续走高才由系统给出升级建议——tier 是**有升降通道的信誉记录**，不是静态标签。

关键原则（来自对技术周刊信源体系的调研）：**载体无罪，看运营主体**——微信公众号不是原罪，字节跳动技术团队的公众号内容与官网博客权威性等价；筛选建立在"运营主体信誉库"上，不是"平台黑名单"上。

## 5. 指标体系（评测详情在 evals/）

**北极星**：主人每周真实使用天数 + 收藏/回查次数（产品是否真的成为"外脑"）。

**质量指标**（黄金集 + LLM-as-Judge，每次改 prompt/换模型必测）：

系统是**三分类路由**（自动发布 / 自动丢弃 / 送人工审），因此**不能用二分类的 precision/recall 评价**——把"我不确定"算成"我认为该收"是把谨慎当成错误（D29）。三条路径分开评：
- **自动发布准确率**：错发代价最高，这是首要指标
- **自动丢弃准确率** + **漏网之鱼清单**（人想要却被自动丢掉的，逐条列出）
- **送审命中率**：太低说明在浪费人的注意力
- 摘要幻觉率（LLM-as-Judge，裁判与主力不同家，判 k 次取多数票并记录裁判分歧率）
- 分类主命中率与 Jaccard 重合度（多标签口径）

**两套评测集，用途不可混淆**（D27）：
- **黄金集**：按分数段分层采样，**无偏**，用于测整体筛选质量
- **边缘区集**：HITL 日常审批自然积累，**有偏**（只存在于送审区间），只能用于调整边缘区处理策略，**绝不能用来改信源 tier**——用有偏样本推翻无偏结论是统计硬错误

**运行指标**：pipeline 成功率、单次运行成本（token 计费）、耗时、降级次数、信源存活率。

## 6. 路线图与现状

- **Week 1 ✅**：pipeline 六 stage 全链路 + 评测 v1
- **Week 2 ✅**：React 前端 + GitHub Issue HITL + Actions 每日运行，**上线 GitHub Pages**（https://wenboxia.github.io/airadar/ ；Vercel 作为可选的额外域名）
- **Week 3**：Phase A ✅（评测污染修复、三分类路由评测、分层采样）· Phase B ✅（知识库视图、内容过期、话题热度与时间线、LLM-as-Judge 幻觉评测）· Phase C 待办（三家模型配对对比，需黄金集 ≥ 60 条）
- **Week 4**：面试武装（decisions 故事线、运行数据量化、3 分钟 demo）
- **Phase 2（面试后）**：对话式知识问答、语义搜索、公众号信源扩充

### 当前实测指标（黄金集 n=26，2026-08-29）

| 指标 | 数值 | 解读 |
|---|---|---|
| 自动发布准确率 | 67% | 自动发布的内容里主人认可的比例——错发代价最高 |
| 自动丢弃准确率 | 100% | **但样本仅 1 条，等于未测**（正是低分段欠采样的证据） |
| **送审命中率** | **20%** | 送人工审的里面只有 1/5 值得收——**80% 审批注意力被浪费**，是明确的待改进点 |
| 漏网之鱼 | **0 条** | 没有一条主人想要的内容被系统自动丢弃 |
| 摘要幻觉率 | 25%（n=8，裁判分歧率 0%） | Kimi 当裁判、判 3 次取多数票 |
| 分类主命中率 | 83% | 多标签口径：人工标的主分类被系统命中即算对 |
