# 黄金集标注辅助 prompt（给 GPT / 其他 AI 用）

## 先说清楚：AI 只能帮你准备资料，不能替你做判断

**能让 AI 做的**：打开链接、读原文、写更详细的中文摘要、整理成方便快速扫的表格。
**绝对不能让 AI 做的**：替你决定 `include` 是 true 还是 false。

两个理由：

1. **面试会穿帮**。这份数据代表你的信源品味，面试官一定会挑一条问"这条你为什么筛掉"。答案得是你自己的。
2. **方法论上是循环论证**（这条更硬，也是个好面试答案）。AIRadar 的 pipeline 本身就是 LLM 在打分。如果黄金集也由 LLM 标注，评测就变成了 **"LLM 评 LLM"**——测的是两个模型像不像，不是筛选质量好不好。黄金集的全部价值在于它是**独立于被测系统的人类标准**。

所以：让 AI 把 26 条的阅读负担降下来，判断你自己做。每条大概 20 秒，全部 26 条 10 分钟内能搞定。

---

## 操作步骤

1. 把 `evals/golden_set/golden_draft.jsonl` 这个文件发给 GPT（或直接粘贴内容）
2. 连同下面这段 prompt 一起发过去
3. 拿到表格后，你逐条判断，把结论填回 `golden_draft.jsonl`
4. 改完**另存为 `golden.jsonl`**（同目录），然后跑 `python3 evals/run_eval.py`

## 直接复制这段 prompt

```
我在给一个 AI 情报筛选系统做评测用的"黄金测试集"。我会给你一个 JSONL 文件，每行是一条被系统抓取的 AI 领域内容。

请你帮我做**资料准备**，让我能快速判断每条内容该不该收进我的长期知识库。

对每一条，请：
1. 打开 url 读原文（打不开就基于 title 和已有摘要说明，并标注"未能访问"）
2. 用 2-3 句中文说清楚：这篇到底讲了什么、有什么具体结论或方法
3. 标注它的信息类型：一手发布 / 深度分析 / 快讯 / 教程 / 观点评论 / 营销宣传
4. 标注时效性：这个信息三个月后是否还成立、还有用

【重要限制】
- 不要给出"建议收录/不建议收录"的判断，也不要打分或排序。判断由我来做。
- 不要美化或补充原文没有的内容。原文信息不足就直说"原文信息有限"。
- 如果多条内容其实在讲同一件事，请指出来（重复报道对我很重要）。

输出格式：一个 markdown 表格，列为「序号 | 标题 | 来源 | 讲了什么 | 信息类型 | 三个月后还有用吗」。表格后面另起一段列出你发现的重复报道。

以下是数据：
[粘贴 golden_draft.jsonl 的内容]
```

## 你自己判断时的标准

**唯一的判断标准**：三个月后，你还愿意在知识库里搜到它吗？

具体一点，帮助你快速决策：

| 倾向收录（include: true） | 倾向筛掉（include: false） |
|---|---|
| 一手发布：新模型、新协议、新工具的官方公告 | 纯商业动态：某公司进入某市场、融资、开分公司 |
| 有方法论的深度内容：怎么做评测、架构怎么设计 | 同一件事的第二、第三次报道（留最权威的那条） |
| 有具体结论的研究：实验、数据、可复现的做法 | 泛泛而谈、没有具体结论的"趋势展望" |
| 三个月后仍成立的原理和经验 | 纯时效快讯：某产品今天上线了某小功能 |
| 与 Agent 工程 / 评测 / 上下文 / 模型能力直接相关 | 与你关注领域无关（哪怕来源很权威） |

**最后一条特别重要**：来源权威不等于内容该收。我们的 pipeline 就丢弃过一条 Simon Willison（A 级信源）写的《EVE Online 迁移到 Python 3》——理由是与 AI Agent 工程无关。**这类"高等级信源的低相关内容"是黄金集里最有价值的样本**，因为它能测出筛选器有没有盲目信任信源等级。

## 填写格式

打开 `golden_draft.jsonl`，每行改这三个字段：

- `include`：`true` 或 `false`
- `category`：从这些里选一个 —— 模型发布 / Agent 工程 / 评测与基准 / 上下文与记忆 / 工程实践 / 开源项目 / 论文 / 行业动态 / 安全与对齐 / 产品与商业
- `note`：**你自己的一句话理由**（把"【待复核】"开头的内容替换掉）

`note` 这一栏别偷懒——面试官问起来，你念的就是这句话。
