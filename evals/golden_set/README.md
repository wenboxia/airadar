# 黄金测试集标注协议

`golden.jsonl` 是评测的**标准答案**——每行一条主人亲手标注的判断。它是评测体系的地基：
没有它，"筛选准不准"只能靠感觉。

## 为什么必须人来标，不能让 LLM 代劳

pipeline 本身就是 LLM 在打分。**如果黄金集也由 LLM 标注，评测就变成"LLM 评 LLM"的循环论证**
——测的是两个模型像不像，不是筛选质量好不好。黄金集的全部价值在于它是
**独立于被测系统的人类标准**。（`ASSIST_PROMPT.md` 提供了让 AI 帮忙**准备资料**的 prompt，
但判断必须人做。）

## 怎么标（工具已就绪，不用手改 JSON）

```bash
python3 evals/prelabel.py --n 25      # 按分数段分层导出草稿（自动跳过已标注的）
python3 evals/review_golden.py        # 逐条标注，断点续标
```

按 `y`（收录）/ `n`（筛掉）/ `s`（跳过）/ `q`（存盘退出）。收录的会让你选分类并写一句理由。

**判断标准只有一句：三个月后你还愿意在知识库里搜到它吗？**

| 倾向收录 | 倾向筛掉 |
|---|---|
| 一手发布：新模型/协议/工具的官方公告 | 纯商业动态：进入某市场、融资、开分公司 |
| 有方法论：怎么做评测、架构怎么设计 | 同一件事的第二、三次报道 |
| 有具体结论的研究：实验、数据、可复现做法 | 泛泛而谈、无具体结论的趋势展望 |
| 三个月后仍成立的原理与经验 | 会被迅速迭代掉的小功能更新 |
| 与 Agent 工程 / 评测 / 上下文 / 模型能力相关 | 与关注领域无关（**哪怕来源很权威**） |

最后一条特别重要：pipeline 就丢弃过 Simon Willison（A 级信源）写的《EVE Online 迁移到 Python 3》。
**"高等级信源的低相关内容"是黄金集里最有价值的样本**——它能测出筛选器有没有盲目信任信源等级。

## 数据格式

```json
{"url": "https://...", "title": "...", "source": "...", "tier": "S",
 "include": true,
 "categories": ["模型训练", "论文"],
 "category": "模型训练",
 "note": "你自己的一句话理由"}
```

- `include`：**唯一必填的判断**——该不该进知识库
- `categories`：**多值**（1–3 个）。一条内容常同时属于多个类别，比如讲量化训练的 arXiv 论文
  既是「论文」（体裁）又是「模型训练」（主题），两者正交，单选会丢信息（D25）
- `category`：主分类 = `categories[0]`，用于排序与雷达图扇区
- `note`：**别偷懒**——面试官挑一条问"这条你为什么筛掉"，你念的就是这句话

## 采样必须分层（D29 的教训）

首版只按 status 采样，结果 80–90 分段标了 11 条，而「自动丢弃」区间只标到 **1 条**
——意味着"该丢的有没有丢掉"这个指标**从未被真正测试过**。

现在 `prelabel.py` 按**分数段**分层（90+/80-90/70-80/60-70/50-60/<50），低分段权重更高：
那里样本稀缺但信息量最大，是唯一能测出误杀与漏杀的区域。

## 评测看的是 `auto_status`，不是 `status`（D28）

条目有两个状态字段：
- `auto_status`：triage 的**原始判断**，只有 triage 能写，人工审批永不覆盖
- `status`：当前状态，HITL 审批会改写

**评测一律用 `auto_status`。** 用 `status` 的话，所有经过人工审批的条目都会变成
"人评人自己"，指标虚高且随着审批增多越来越失真——这个 bug 真实发生过。

## 目标规模

**100 条**。统计依据：精确率的 95% 置信区间在 n=16 时是 ±22pp（等于没测）、n=60 时 ±12pp、
n=100 时 ±9pp。且精确率只在"系统已发布"的子集上计算，100 条标注实际约 65 条参与。

黄金集**只增不删**；标错了用 `"deprecated": true` 标记，保留痕迹。
