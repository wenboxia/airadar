# 黄金测试集标注协议

`golden.jsonl` 是评测的**标准答案**——每行一条主人亲手标注的判断。它是评测体系的地基：
没有它，"筛选准不准"只能靠感觉。

## 为什么必须人来标，不能让 LLM 代劳

pipeline 本身就是 LLM 在打分。**如果黄金集也由 LLM 标注，评测就变成"LLM 评 LLM"的循环论证**
——测的是两个模型像不像，不是筛选质量好不好。黄金集的全部价值在于它是
**独立于被测系统的人类标准**。（`ASSIST_PROMPT.md` 提供了让 AI 帮忙**准备资料**的 prompt，
但判断必须人做。）

## 怎么标（工具已就绪，不用手改 JSON）

```bash
python3 evals/prelabel.py --n 100     # 分数段分层 + 段内随机抽样（自动跳过已标注的和已停抓的信源）
python3 tools/prep_golden_doc.py      # AI 写资料 → 生成 Word 标注表（黄金集v2_标注表.docx）
python3 evals/import_golden_docx.py   # Word 表写回 golden.jsonl；中途导也行，改过的行会替换旧记录（旧的标作废）
```

Word 表只填最右边三列：收录（y/n）、分类（1–3 个，顿号分隔）、一句理由。
不想用 Word 的话，`python3 evals/review_golden.py` 可以在命令行逐条标：`y` 收录 / `n` 筛掉 / `s` 跳过 / `q` 存盘退出。

**判断标准只有一句：三个月后你还愿意在知识库里搜到它吗？**

### v2 标准（2026-09-16 起，D35）

旧标准没写成文，靠感觉判，结果收录的 12 条里有 4 条是普通 arXiv 预印本。
v2 按「对 AI 产品经理的价值」从高到低排，**每一条都要能解释我已经做过的否决**：

| 优先级 | 类型 | 收 | 不收 |
|---|---|---|---|
| 1 | **一手发布** | 模型、产品、协议、工具的官方公告与工程博客 | 同一件事的第二、三次报道（留最权威那条） |
| 2 | **顶尖从业者的判断** | Karpathy、Simon Willison、实验室员工等公开讲的具体观点 | 泛泛而谈、没有具体结论的趋势展望 |
| 3 | **影响技术格局的公司动态** | 收购、重大人事变动、算力投入、模型定价大改——会改变技术选型的 | 区域市场扩张、教育合作、公益活动、纯政策评论（例：已否掉的「OpenAI 进军巴西」「The turbulent AI era」） |
| 4 | **开源项目** | 有新做法、能直接拿来用或学的 | 套壳、换皮、无创新的仿造品。**star 数不是门槛**（收过 1,135 star 的 pi-from-scratch，否过 6,602 star 的 kimi-k3-in-c） |
| 5 | **论文（门槛最高）** | 今天正在被实质讨论的：官方或顶尖从业者专门讲过、HN 上高分高讨论；作者是实验室或几十人署名的技术报告 / System Card（本质是产品发布） | 只出现在参考文献里的；没有任何外部讨论的普通预印本 |

几条补充：

- **论文看的是「今天有没有人在讨论」，不是发表时间**（D36）。一个月前的论文今天才被讨论，今天收录就是对的；一两周一篇都没有也正常
- **来源权威不等于该收**。pipeline 丢弃过 Simon Willison（A 级）写的《EVE Online 迁移到 Python 3》。
  「高等级信源的低相关内容」是黄金集里最有价值的样本——它测的是筛选器有没有盲目信任信源等级
- **营销稿要筛掉**，哪怕来自官方。v1 黄金集里系统送审、被人否掉的 8 条，有 3 条是营销宣传、2 条是无创新仿造品

### 资料准备可以交给 AI，判断不行

AI 可以写「讲了什么」「信息类型」「三个月后还有没有用」「重复提示」，**不能**给收录建议（边界见 `ASSIST_PROMPT.md`）。

实际执行时没完全守住这条：v2 语音标注中，ChatGPT 在 42 条上先说了"建议收 / 不收"，其中 4 条主人直接用了它的理由。
这些都逐条记在 `ai_recommended_first` / `note_source` 里；去掉那 4 条，评测结论不变（D42）。

v2 的标注表里**同时显示了系统的分数与判断**。这是明知有锚定风险之后的选择：
标注者可能不自觉地跟着系统走，让评测结果偏乐观。主人的判断是自己能独立下结论，
且看到系统判断能更快定位分歧。所以解读 v2 的一致率时要记住这个前提——
如果将来要做更严格的对比，应该另标一批不显示系统判断的样本，看两批的一致率差多少。

## 数据格式

```json
{"url": "https://...", "title": "...", "source": "...", "tier": "S",
 "include": true,
 "categories": ["模型训练", "论文"],
 "category": "模型训练",
 "note": "你自己的一句话理由"}
```

- `include`：**唯一必填的判断**——该不该进知识库
- `categories`：**多值**（1–3 个），取值以 `pipeline/stages/classify.py` 的 `CATEGORIES` 为准。一条内容常同时属于多个类别，比如讲量化训练的 arXiv 论文
  既是「论文」（体裁）又是「模型训练」（主题），两者正交，单选会丢信息（D25）
- `category`：主分类 = `categories[0]`，用于排序与雷达图扇区
- `note`：**别偷懒**——面试官挑一条问"这条你为什么筛掉"，你念的就是这句话

## 采样必须分层（D29 的教训）

首版只按 status 采样，结果 80–90 分段标了 11 条，而「自动丢弃」区间只标到 **1 条**
——意味着"该丢的有没有丢掉"这个指标**从未被真正测试过**。

现在 `prelabel.py` 按**分数段**分层（90+/80-90/70-80/60-70/50-60/<50），低分段权重更高：
那里样本稀缺但信息量最大，是唯一能测出误杀与漏杀的区域。

**段内必须随机抽**（D35）。之前段内按分数从高到低取前 N 条，结果 0–50 段只采到 47–49.9 分、
60–70 段全是 69.x——"分层"只是名义上的。现在段内随机抽（固定种子 `--seed`，可复现）。

## 评测看的是 `auto_status`，不是 `status`（D28）

条目有两个状态字段：
- `auto_status`：triage 的**原始判断**，只有 triage 能写，人工审批永不覆盖
- `status`：当前状态，HITL 审批会改写

**评测一律用 `auto_status`。** 用 `status` 的话，所有经过人工审批的条目都会变成
"人评人自己"，指标虚高且随着审批增多越来越失真——这个 bug 真实发生过。

## 目标规模

**100 条**（v2 实际 111 条）。统计依据：精确率的 95% 置信区间在 n=16 时是 ±22pp（等于没测）、n=60 时 ±12pp、
n=100 时 ±9pp。且精确率只在"系统已发布"的子集上计算，100 条标注实际约 65 条参与。

黄金集**只增不删**；标错了用 `"deprecated": true` 标记，保留痕迹。

  - **2026-09-17 标完，共 111 条**：100 条语音标注 + 11 条从 v1 复用（与 v2 不重复、不违背 v2 判断逻辑、信源仍在抓）。

  - **标注方式**：主人和 ChatGPT 语音聊天，逐条口头决定收不收、说理由，ChatGPT 念资料、查原文、代填

  - **不标分类**：分类体系在重新理清，分类准确率改用官网自带标签测

## 字段说明（v2）

| 字段 | 含义 |
|---|---|
| `include` | 主人的决定 |
| `note` | 最终理由：主人原意在前，后面可能补了 AI 提到的具体事实 |
| `note_user` | 主人原意整理版（不含补充） |
| `note_ai_points` | 补进 `note` 的 AI 要点及出处（聊天记录行号） |
| `note_source` | 本人 / 本人+AI查证 / 采纳AI / 批量，有补充的加「+AI补充」 |
| `ai_recommended_first` | 主人表态前 AI 是否先给过"建议收 / 不收" |
| `note_docx` | Word 表里 AI 代填的版本，只留痕，不参与评测 |
| `note_v1_raw` | v1 复用条目的原始理由（`note` 只修了错字） |

聊天记录全文（`我和gpt语音聊天让他辅助我标注.txt`）含无关闲聊和本机路径，只留在主人本地，不进仓库。
